## Tables

| Table | Columns | Notes |
|---|---|---|
| `sellers` | seller_id, seller_name, store_name, joined_date | |
| `listings` | seller_id, sku, title, category, price_usd, stock_qty, status, description | status: Out of Stock at 0, Low Stock at 1–5, Active above 5 (one deliberate exception, below). Descriptions include dimensions, except where a gap is intended |
| `price_history` | seller_id, sku, price_usd, valid_from, valid_to | Empty valid_to = current price. Needed for price drift and "was" price questions |
| `orders` | order_id, seller_id, sku, order_date, quantity, unit_price_usd, order_total_usd, status, promised_delivery_date, delivered_date, issue_note | status: delivered, in_transit, delayed, cancelled, returned, return_requested. Unit price comes from price_history on the order date |
| `sales` | date, seller_id, sku, units_sold, revenue_usd, order_count | Derived from orders: every order except cancelled ones, summed per day and SKU. Returns stay visible in orders |
| `reviews` | seller_id, review_id, sku, order_id, rating, comment, review_date | Original reviews have no order_id |

## Awkward cases, on purpose

- "Throw" matches several listings (pillow cover set, Sherpa blanket, chunky knit throws); "macrame" matches two.
- 12 of Meera's listings never sold in the window; most listings have no reviews.
- A few orders are delayed or have open return requests right now.
- No listing contains "velvet": a question about a velvet cushion must find nothing.
- Some titles appear for both sellers. The agent must only ever answer with the asking seller's data.

## Simplifications

Sales are gross (returns are not subtracted). About 15–18% of delivered orders get a review. Stock levels are a snapshot for "today" and are not decremented by each order.
